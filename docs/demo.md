# 本地演示操作单

先按 README 启动服务。无 DeepSeek key 时使用端口 8001、`USER_ID=demo-offline` 的显式 fake 模式。下面区分可重复的流程演示与待运行的真实模型检查；fake 的规则性回答不用于证明语义理解。

## 开场与准备

1. 运行 `python scripts/preflight.py`，或 fake 模式对应的带环境变量命令。展示 provider、database 和模式标识，不展示 `.env` 内容。
2. 在页面新建 Course“梯度下降入门”，主题填“微积分、导数、梯度和梯度下降”。在“资料库”上传 `data/demo_gradient.md`；这是原创流程样例，不是人工审定的课程评测集。
3. 等待材料状态。如果为 `accepted`，检查概念列表及图中的关系；`uncertain` / `conflict` / `rejected` 均须解释原因，不能当成已纳入的知识。新概念初始掌握状态应为“未测”，不因上传资料直接获得分数。

## 普通请求：有来源的回答

在“对话”输入：“请解释梯度下降为什么沿负梯度更新。”观察回答、右侧“本次证据”和页码/片段，再点“查看原文”。引用必须来自本轮可见的检索证据，quote 应能在对应原文中找到。来源 URL 字段是出处记录，不会因上传自动抓取网页。

公开 PDF 可用 `python scripts/fetch_materials.py` 下载，随后手动上传 `runtime/materials/transformer.pdf` 到适合机器学习/Transformer 的 Course；RAG 可单独上传到相应 Focus。上传时使用 `data/sources.json` 对应的 `source_url`。材料审核可能因证据不足而返回 `uncertain`，不能为顺利演示而改写成通过。真实 PDF 的概念抽取与回答质量须在配置 key 后另行检查。

## 改变条件：答错后调整与恢复

1. 打开“引导学习”，选择“梯度下降”等目标，点击“开始学习”。若前置导数/梯度尚未掌握，轨迹应显示先处理前置概念。
2. 阅读讲解并提交一个错误选项。fake 演示可选第二项；这是确定性提供器的演示规则，不能套用于真实模型。
3. 检查反馈确实为错误，错误历史和尝试数增加一次；教学切到 `example`，出现新的题目与新的 quiz ID。不要替学生自动作答。
4. 根据新的例子再作答。fake 可选第一项；真实模式按题目内容选择。正确回答更新当前概念的记录，继续练习；是否推进同时取决于分数与连续正确次数，答错后不保证“两次正确就推进”。
5. 刷新网页，确认当前课程、会话及题目恢复。再按 `Ctrl-C` 停止应用，用相同 provider、`USER_ID` 和端口重启，重新打开页面，确认同一会话仍在，错误/尝试记录未丢失。
6. 点击停止学习，确认会话状态为 `stopped`、不再显示活动测验。停止的会话不能靠“恢复”继续；需要开始新会话。停止不清除已有学习记录。

同时可在对话提出：“纠正：之后统一用列向量表示输入。”在相同聊天继续追问，检查轨迹和最终模型输入预算相关测试。显式偏好通过“学习偏好”保存；再次提交相反偏好时旧项失效并保留历史。fake 只验证保存/范围，不证明真实回答会充分遵守偏好。

## 空间隔离与 Focus 纳入

- 新建第二个 Course，先不上传材料：应看不到第一门课的概念、作答或对话。切回第一门课，记录应仍存在。
- 新建单材料 Focus，上传一份材料；将其纳入匹配主题的 Course 时重新审核。两个空间可共享原件，但概念与掌握记录独立；审核不通过不进入目标 Course 检索。
- 空间之外的 concept/document/session/chat ID 由 API 拒绝。对应自动化检查在 `tests/test_api_flow.py`、`tests/test_knowledge.py`，不以“页面切换看起来正常”代替服务端隔离检查。

## 失败请求与有界恢复

| 操作 | 应检查的行为 | 恢复方式 |
|---|---|---|
| DeepSeek key 留空后以真实模式启动 | 顶部待配置；预检退出 `2`；不调用生成，不伪造真实回答 | 本地填写 key、重启，再显式运行 `--probe-real` |
| 上传内容不是 PDF 的 `.pdf`，或再次上传相同文件 | 分别为 `rejected` / `duplicate`；不能增加有效检索材料 | 上传可解析且未重复的资料 |
| 当前课程问“这个问题与当前课程无关，请讲另一门课” | 澄清范围；不得借其他 Course 的知识或记忆作答 | 切换正确空间或修改问题 |
| 问当前材料没有依据的问题 | 真实模式可能先检索和验证限定 arXiv 来源，仍不足则说明缺口；禁用搜索时直接保留缺口 | 补充材料或缩小问题；fake 不证明缺口识别质量 |
| 模型超时/429/503或非法结构化结果 | 有界重试/修复；仍失败则返回错误或暂停可恢复会话，不能切 fake | 恢复依赖后刷新状态，使用页面恢复操作；以实际失败轨迹为准 |
| 对同一测验重复提交、提交旧 quiz ID | 同一 submission ID 幂等；旧题的新提交返回 `409`，不重复加分 | 获取当前会话并回答当前题目 |

网络超时、格式错误、并发重复提交等稳定通过模拟故障测试重现；不需要现场故意关闭数据库或消耗真实 API 配额。三次连续错误、步数上限、完成与用户停止都有终止路径，详见轨迹及测试。

## 两分钟 pitch 提纲

- 0:00–0:20：说明问题：学习资料分散、回答难追溯、答错后缺少针对性调整。StudyAgent 把课程资料和学习状态放在明确空间内。
- 0:20–0:50：上传已测试的原创样例，提问并打开引用。强调材料审核和引用校验是筛选机制，不能保证事实绝对正确。
- 0:50–1:25：启动目标概念，提交错误答案，展示实际执行的 example 和新题；再答一次，看掌握记录更新。解释分数只是透明的启发式。
- 1:25–1:45：刷新恢复待答题，展示稳定会话；点击停止，不再调用工具。说明 PostgreSQL 同时保存业务数据和 LangGraph 检查点。
- 1:45–2:00：报告已测证据：50 项程序测试、隔离安装与 HTTP 检查；当前画面为 fake 流程演示，DeepSeek 真实质量尚待配置 key 后评估。回答追问时可现场改变问题、偏好或空间。

按实际服务速度调整演示节奏。真实模式的生成时延尚未测量，不能承诺两分钟内完成所有网络请求。
